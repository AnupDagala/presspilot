# Provider configuration and honest modes

Baseline is deterministic code. Mocked runs use a fixed synthetic response sequence selected from the request interpretation; they exercise the model/tool boundary without a provider call. Four contract fixtures check real provider API envelope shapes. None constitute paid or live inference.

For live execution, use a **private evaluation organization**, `SANDBOX_ENABLED=false`, `LIVE_MODEL_ENABLED=true`, an explicit `MODEL_PROVIDER` and `MODEL_ID`, and server-only credentials. `scripts/provision-session.mjs` creates a private fictional order and separate one-hour operator, approver and administrator sessions using a protected database connection file. It prints only the organization ID and private token-file locations under ignored `runtime/secrets/private-<role>-session`. Give each person only their authorized role token. Sign in using the console's private session form; tokens are never stored in browser localStorage. Sandbox role switching is unavailable for private organizations.

| Provider                         | `MODEL_PROVIDER` | Secret name         | Fixed approved endpoint                             |
| -------------------------------- | ---------------- | ------------------- | --------------------------------------------------- |
| OpenAI                           | `openai`         | `OPENAI_API_KEY`    | `https://api.openai.com/v1/responses`               |
| Claude                           | `anthropic`      | `ANTHROPIC_API_KEY` | `https://api.anthropic.com/v1/messages`             |
| Grok                             | `xai`            | `XAI_API_KEY`       | `https://api.x.ai/v1/chat/completions`              |
| Open-weight through Hugging Face | `openweight`     | `INFERENCE_API_KEY` | `https://router.huggingface.co/v1/chat/completions` |

Secrets support either environment injection by Secret Manager or `<NAME>_FILE` paths. Never pass credential values on a command line or add them to the repository. `MODEL_ENDPOINT`, if supplied, must exactly equal the approved endpoint for that provider. Adding an inference destination requires a reviewed code change. Private/local/IP destinations and redirects are rejected. Use a tool-capable model supported by the chosen endpoint; no identifier or price has been invented as a recommended default.

Recorded configuration includes provider, configured model, returned model in observations, endpoint, output cap, prompt version, mode, tool/turn counts and reported input/output usage. The evaluator measures wall-clock latency separately; changing elapsed time is deliberately excluded from idempotent tool arguments. Persisted responses are reused after activity recovery. Provider-specific reasoning continuation features have not been live-tested. Usage omission, malformed tools, ambiguous delivery, unsafe output and exhausted budgets escalate. Pending reservations remain charged conservatively if the response is lost. Model activities have finite deadlines; the application does not guarantee a model supports every request shape.

The API must also receive `MODEL_MAX_USD_PER_MTOK` (a conservative upper bound for the higher input/output price of the configured model) and `MODEL_DAILY_USD_LIMIT`. Both must be positive; unset values disable live reservations. The backend bounds estimated daily spend by charged/reserved tokens × the configured worst-case rate. Obtain rates from official provider pricing and record the assumptions; this is a configured estimate, not provider billing verification. Do not enter guessed prices. No provider price is bundled as a factual default.

Run `npm test` for no-cost wire contracts. Live trials must be explicit, private, bounded and reported separately. No credentials were available during implementation; live execution and pricing are unverified.

The optional live evaluator creates isolated, expiring private fictional fixtures through the test runner's protected database connection. Set `EVAL_MODE=live`, `LIVE_EVAL_ENABLED=true`, `LIVE_EVAL_CASE_IDS=C01-queued-cancel,M01-gloss,C04-production-cancel`, and `LIVE_EVAL_TRIALS=1`, then run `npm run eval`. At most three cases and three trials are permitted, with server-side global spending/call/token limits still enforced. Raise those limits only within an explicitly approved budget. The runner performs simulated changes and approvals only on its own fictional fixtures, never Shopify. Reports remain under ignored `runtime/private-evaluations`; private results are not published to the public console automatically. Expected answers stay in the grader. Reservations, observed usage, exact configuration, failures and measured latency are reported; billing and ambiguous deliveries are not inferred. This path has not made live provider calls. `EVAL_PRIVATE_FIXTURES=true EVAL_MODE=mocked` verifies the private fixture and authorization path without paid calls.

For one investigation without approval, use `npx tsx tests/live-smoke.ts` with `LIVE_TEST_ENABLED=true` and `PRIVATE_SESSION_TOKEN_FILE=runtime/secrets/private-operator-session`. It is a smoke test, not a repeated-trial benchmark.

Official contracts reviewed: [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling), [Claude tool-call handling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls), [xAI Chat Completions](https://docs.x.ai/developers/rest-api-reference/inference/chat-completions), and [Hugging Face Chat Completion](https://huggingface.co/docs/inference-providers/tasks/chat-completion).
