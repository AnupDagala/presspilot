# Verification evidence

This file records measured results, not planned checks. Implementation date: 1 October 2026, Asia/Kolkata.

First vertical slice: actual PostgreSQL and Temporal; cancellation submission, evidence retrieval, persisted proposal, approval, atomic execution and audit. Initial tests exposed an integer/text SQL comparison and noncanonical nested JSON hashing. Both were fixed and regression-tested.

The initial 60-case baseline run passed 59/60. Its failure was the evaluator attempting to switch a session after revoking that session's membership. The evaluator now switches to an authorized administrator before revocation; the backend still revalidates and rejects the revoked approver. The corrected full run passed **60/60** (40 development, 20 held-out, one trial each), median wall-clock **1,136 ms**, p95 **7,504 ms**. It includes 53 PostgreSQL/Temporal business/workflow scenarios and seven recorded provider contracts. No paid model calls or model tokens were used. This is baseline/system performance, not model performance.

Final full runs passed **60/60 baseline** and **60/60 mocked** on actual PostgreSQL and Temporal, one trial each. Baseline p50/p95: **1,109/12,268 ms**. Mocked private-fixture p50/p95: **1,126/8,103 ms**. These wall-clock measurements include approval polling, worker startup/recovery and other verification work on the same host; they are not load benchmarks or model performance. Both reports contain per-trial configuration and failure categories. Seven tasks in each suite are recorded provider contracts; 53 are business/security/workflow tasks. No paid calls occurred.

An initial private-fixture run passed 58/60 because the test driver attempted to use a sandbox-only production simulation endpoint. The backend correctly rejected it. The driver now injects a labelled production event only into its own private fictional fixtures; the corrected full suite passed 60/60. Expected answers remain outside the worker.

The hard process-kill test initially found a real recovery defect: elapsed latency changed an idempotent `record_run` input when an unfinished activity retried. Latency is now measured separately. Model observations are persisted and retrieved on recovery; an ambiguous provider delivery retains its reservation and escalates. Final baseline and mocked process-kill checks each verified **one order retrieval and one business effect** after approval while the worker was down.

Six final browser tests passed through the production Node web gateway (32.0 seconds): submission/evidence/approval, rejection, stale approval, responsive keyboard use, honest evaluation-mode presentation, and administrator-only review without an order effect. A separate actual browser check verified private operator/approver sign-in, denied sandbox role escalation, disabled operator approval and completed an authorized fictional cancellation. Test session credentials were removed from the deliverable checkout afterwards. Private sign-in test selectors were corrected to match the combined status/role header; the API authentication check itself succeeded.

Go tests passed 18 test functions plus approval-expiry/rejection/revocation subtests. They cover atomic/idempotent execution, concurrent approvals, evidence invalidation, tenant and role permissions, narrow tools, persisted responses, application-wide budget races, webhook signatures/deduplication and tracing without captured secrets. Provider contract and baseline unit tests passed **12/12**. Local OpenTelemetry console export was observed for actual GraphQL traffic. An actual PostgreSQL custom-format dump restored into an isolated scratch database with **zero duplicate effects and zero mismatched approval bindings**; the scratch database and dump were removed. Cloud/Temporal joint restoration remains unverified.
